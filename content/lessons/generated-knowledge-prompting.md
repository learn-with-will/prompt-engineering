> **In one line:** Generated Knowledge prompting elicits relevant domain facts from the model before answering commonsense questions.

## The idea

Commonsense reasoning questions often require unstated background world knowledge that is not mentioned in the query itself. For example, answering *"Can a penguin survive in a desert?"* requires knowing that penguins possess thick blubber adapted for sub-zero temperatures and depend on marine prey.

In their 2021 paper (*Generated Knowledge Prompting for Commonsense Reasoning*, arXiv:2110.08387), Jiacheng Liu and colleagues demonstrated that prompting an LLM to explicitly generate a set of relevant facts before attempting to answer significantly boosts accuracy on commonsense reasoning benchmarks.

The technique operates in two distinct phases:
1. **Knowledge Generation**: Given the question, prompt the model to generate 3–5 factual assertions, physical properties, or background facts relevant to the entities involved.
2. **Knowledge Integration**: Feed the generated facts alongside the original question into an integration prompt to deduce the final answer.

| Benchmark | Standard Zero-Shot | Generated Knowledge Prompting |
|---|---|---|
| **NumerSense** (Numerical commonsense) | 48.9% | **58.6%** (+9.7% gain) |
| **CSQA** (Commonsense QA) | 68.2% | **73.3%** (+5.1% gain) |
| **QASC** (Science reasoning) | 58.8% | **66.2%** (+7.4% gain) |

## See it

```python
# Implementing the two-phase Generated Knowledge pattern
def solve_with_generated_knowledge(question: str) -> str:
    # Phase 1: Generate domain background facts
    knowledge_prompt = f"""Generate 3 to 4 factual properties and background knowledge
statements relevant to answering this question:
Question: {question}
Relevant Facts:"""
    facts = call_llm(knowledge_prompt)
    
    # Phase 2: Integrate generated knowledge to produce the final answer
    answer_prompt = f"""Background Knowledge:
{facts}

Question: {question}
Based on the background knowledge above, provide the final answer with a brief justification:"""
    return call_llm(answer_prompt)
```

## Go deeper

Crucially, **generated knowledge is NOT verified external knowledge**. Because the facts are generated by the model itself, they can contain plausible hallucinations. While highly effective for commonsense reasoning and general physics, **never rely on generated knowledge for high-stakes medical, legal, or financial questions**. In factual domains, retrieve knowledge from an external RAG database instead.

> **Watch out:** If the model hallucinates a false premise during the knowledge generation phase, it will double-down on that error in the subsequent answer phase.

## Watch out

- Using generated knowledge prompting for live data, stock prices, or facts after the knowledge cutoff.
- Trusting generated knowledge in regulated domains without external database verification.

## Remember

- Generated Knowledge prompts the model to articulate relevant background facts before answering.
- Liu et al. demonstrated 5–10% accuracy gains across commonsense reasoning benchmarks.
- Useful for commonsense reasoning, but never substitute generated knowledge for verified RAG in factual domains.
